# 발전소별 다음날 0~23시 발전량 예측

## 변경된 학습 방식

과거 **3일 × 24시간 = 72개 시간별 발전량**을 입력하고, **다음날 0~23시의 24개 시간별 발전량**을 출력한다. 하루 평균이나 7일 평균으로 학습하지 않는다. 하루 총발전량은 24개 예측값을 합산한 파생 결과다.

원본의 `금일발전량`은 하루 누적량이다. 인버터·날짜별로 시간 차분하고 0시는 해당 누적값을 사용한다. 이후 같은 지역·같은 시간의 인버터 발전량을 합산한다. 전체 자료에서 이렇게 만든 시간별 값의 하루 합계가 23시 누적값 합계와 정확히 일치함을 확인했다. 시간 표기는 원본 0~23시 라벨을 유지하며, 센서의 집계 구간 시작/종료 규약은 별도 확인이 필요하다.

독립적인 발전소 ID가 없으므로 원본 `발전소 지역`의 13개 지역을 발전소 단위로 사용한다. 상세 인버터 매핑은 `artifacts/preprocessing.json`에 있다. GRU 하나와 TFT 하나가 발전소 ID 임베딩을 사용해 공동 학습하며, 예측값과 성능은 발전소별로 구분한다. 발전소마다 별도 가중치 파일을 만든 26개 모델 방식은 아니다.

## 데이터와 분할

| 구분 | 목표 날짜 | 발전소·일 시퀀스 수 | 시간별 목표 수 |
|---|---|---:|---:|
| 학습 | 2025-01-04~09-30 | 3,510 | 84,240 |
| 검증 | 2025-10-01~12-31 | 1,196 | 28,704 |
| 테스트 | 2026-01-01~03-31 | 1,170 | 28,080 |

학습 원자료는 2025-01-01부터이며 첫 72시간은 입력 이력이다. 예측은 하루 한 번, 전날 23시 관측을 수신한 뒤 다음날 전체를 출력한다. 검증과 테스트에서도 매일 전날까지의 실제 관측을 사용한다. 미래 시간의 발전량을 재귀 입력하지 않는다. 모든 설비에 동일한 날짜 경계를 적용하며 무작위 분할은 하지 않는다.

`data/*_hourly.csv`에는 분리된 시간별 원단위 발전량이 있다. `*_windows.csv`에는 실제 학습/평가 시퀀스의 입력 시작과 예측 시작 인덱스가 있다. `hourly_all.csv`는 추론 재현용 전체 전처리 자료다.

## 모델

- 작은 GRU: 1층 hidden size 32, 발전소 embedding 4, 다음날 시간별 달력 특성을 결합한 MLP 출력층.
- 작은 TFT: PyTorch Forecasting의 실제 TemporalFusionTransformer. hidden size 16, LSTM 1층, attention heads 2, continuous hidden size 8.
- 과거 입력: **시간별 발전량**. 날짜·시간 sin/cos와 발전소 ID를 함께 사용한다.
- 기상값, 센서 온도, 전류, 7일 평균은 이번 모델 입력에 포함하지 않는다.
- 발전소별 학습 기간 시간평균으로 발전량의 크기만 정규화한다. 이는 시간별 자료를 평균값으로 대체하는 처리가 아니다. 각각의 0~23시 값은 그대로 시퀀스에 유지된다.
- 두 모델 모두 다음날 24개 값의 정규화 MAE로 학습한다. 최대 40 epoch, 조기 종료 patience 6, 검증 손실 최저 체크포인트를 저장한다.
- 출력은 원단위로 되돌리고 음수를 0으로 제한한다. 야간값을 임의로 0으로 덮어쓰지 않는다.

## 평가

시간별 WAPE/MAE/RMSE와 24시간 합계의 일일 WAPE를 각각 저장한다. 서로 다른 예측 단위의 지표를 혼동하지 않는다. 시간별 오차가 하루 합산에서 상쇄될 수 있으므로 시간별 지표가 주 평가 기준이다.

비교군은 **전날 동일 시간값 24개**다. 7일 평균은 포함하지 않는다. 모든 모델은 같은 시점에 알 수 있는 정보로 평가한다. 06~19시 구간과 보정 표시 없는 차분 목표 구간도 별도 평가한다. 차분 목표는 현재와 직전 누적값 중 하나라도 Y이면 보정 구간으로 표시한다.

최종 신경망 선택은 검증 시간별 WAPE로 한다. 테스트 결과를 보고 재튜닝하지 않는다. 원자료의 결측보정이 미래 값을 사용했는지 확인할 수 없어 데이터 원천 단계의 누출 위험은 남는다.

## 사용

Python 3.12와 `requirements.txt` 패키지를 사용한다. 현재 작업에서 만든 Python 환경은 프로젝트 디렉터리 기준 `../../work/solar_py312/Scripts/python.exe`다.

```powershell
python -m pip install -r requirements.txt
python train.py --csv "원본 CSV 전체 경로" --epochs 40
python predict.py --as-of 2026-03-31
```

`predict.py`는 체크포인트를 다시 불러와 다음날의 **발전소별 24행**을 저장한다. `--hourly` 옵션에 `data/hourly_all.csv`와 같은 열 구조의 전처리 자료를 전달할 수 있다. `--as-of`는 자료가 완료된 마지막 날짜다. 체크포인트는 이 프로젝트에서 생성된 신뢰할 수 있는 파일만 로드한다.

## 결과 파일

- `artifacts/GRU/best.ckpt`, `artifacts/TFT/best.ckpt`: 학습된 모델.
- `artifacts/*_hourly_predictions.csv`: 발전소·날짜·시간별 실제/예측값.
- `artifacts/*_daily_sums.csv`: 24시간 합계.
- `artifacts/site_metrics.csv`: 발전소별 성능.
- `artifacts/metrics.json`: 전체 성능·학습 이력 요약.
- `artifacts/next_day_hourly_forecast.csv`: 2026-04-01 시간별 예측 예시. 실제값으로 검증된 날짜가 아니다.
- `artifacts/logs/`: epoch별 손실.

발전량 단위는 원자료 숫자 단위이며 kWh로 확정하지 않았다. 현재 날짜의 실시간 예측이 아니라 2026-03-31까지의 데이터로 학습한 모델이다. 테스트는 한 분기이며 원자료 보정 문제와 기상예보 부재를 고려하여 해석한다.
